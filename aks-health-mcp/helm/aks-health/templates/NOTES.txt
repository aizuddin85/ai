─── Check pods ──────────────────────────────────────────────────

  kubectl get pods -n {{ .Release.Namespace }} \
    -l app.kubernetes.io/instance={{ .Release.Name }}

─── Verify health probes ────────────────────────────────────────

  kubectl exec -n {{ .Release.Namespace }} \
    deploy/{{ include "aks-health.fullname" . }}-backend \
    -- wget -qO- http://localhost:8000/healthz

─── Access the application ──────────────────────────────────────

{{- if .Values.ingress.enabled }}
{{- $scheme := ternary "https" "http" .Values.ingress.tls.enabled }}
  Application: {{ $scheme }}://{{ .Values.ingress.host }}
  API docs:    {{ $scheme }}://{{ .Values.ingress.host }}/api/docs
{{- else }}
  No Ingress is enabled.  Use port-forward for local access:

    # Backend API
    kubectl port-forward -n {{ .Release.Namespace }} \
      svc/{{ include "aks-health.fullname" . }}-backend 8000:8000

    # Frontend  (visit http://localhost:8080)
{{- if .Values.frontend.enabled }}
    kubectl port-forward -n {{ .Release.Namespace }} \
      svc/{{ include "aks-health.fullname" . }}-frontend 8080:8080
{{- end }}
{{- end }}

─── Logs ────────────────────────────────────────────────────────

  kubectl logs -n {{ .Release.Namespace }} \
    -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=backend \
    --tail=50 -f

─── Troubleshooting ─────────────────────────────────────────────

If pods are not starting check:
  • AZURE_TENANT_ID is a valid GUID (config.azureTenantId)
  • AZURE_SUBSCRIPTION_IDS is set (config.azureSubscriptionIds)
  • AZURE_FOUNDRY_ENDPOINT is set (config.azureFoundryEndpoint)
  • The ServiceAccount has the correct Workload Identity annotation
    or that Service Principal credentials are set in the Secret
